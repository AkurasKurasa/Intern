# Objective 7 re-run with UI.Vision RPA

The first comparison used a PyAutoGUI script in place of an RPA product (Sec 3.3.5:
"UI.Vision … was not available on the test computer"). This folder re-runs the Scope 1
comparison with **UI.Vision RPA** itself, the tool the panel chair named. Everything else stays
the same: the normal and modified forms, record 1, 5 + 5 runs, and the scoring. Intern is not
re-run; its 10 runs on the same forms and record are reused.

The macro sends exactly the same keys and clicks as the PyAutoGUI script did
(`tests/test_rpa_uivision.py`), so only the RPA product changes.

## One-time setup (about 10 minutes, by hand)

1. **Install the UI.Vision desktop module (XModules v2).** It gives UI.Vision real mouse and
   keyboard input on the desktop.
   - Download: <https://download.ui.vision/x2/uivision-desktop-win-2.1.43.exe>
     (signed by a9t9 software GmbH, the maker of UI.Vision).
   - Double-click it. If Windows SmartScreen warns, click **More info → Run anyway**. It installs
     for your user only and needs no admin rights.
2. **Open the dedicated browser:** `python scripts/rpa_uivision.py browser`
   This opens a separate Chrome profile used only for these runs, so your own Chrome is never
   touched. It shows the UI.Vision page in the Chrome Web Store and `chrome://extensions`.
3. On the Web Store tab, click **Add to Chrome**.
4. On the `chrome://extensions` tab, open **UI.Vision → Details** and turn on
   **Allow access to file URLs**.
5. Click the puzzle icon → **UI.Vision**. In its window, open **Settings** (gear icon):
   - **Advanced → API**: tick **Run embedded macros from local files**.
   - **Desktop Automation → Setup (XModules2)**: check that it shows the desktop module as
     installed/connected.
6. Close that Chrome window.

## Runs (you start them; do not touch the PC while they run)

```
python scripts/rpa_uivision.py run --only gate     # 1 run on the normal form, scored at once
python scripts/rpa_uivision.py run                 # 5 normal + 5 modified (about 25-30 min)
python scripts/rpa_score.py --sheet docs/rpa_comparison/run_sheet_uivision.csv --submissions docs/rpa_comparison/submissions
```

Each run opens a fresh form at the top-left of the main screen, keeps it above other windows,
and starts UI.Vision in the dedicated Chrome on the second screen. UI.Vision clicks the first
field, types record 1 in the normal form's Tab order, and clicks Submit. The macro is built once on
the normal form (`build`) and **not edited** before the modified-form runs.

If the gate does not end with "fully correct = True", stop and check the printed wrong fields
before running the 10 runs.

## Files

| File | What it is |
|---|---|
| `Objective7_Scope1_Record1.json` | The UI.Vision macro (can also be imported in UI.Vision to view or play it) |
| `run_macro.html` | Local page that hands the macro to UI.Vision (its embedded-macro mechanism) |
| `build.json` | Screen coordinates and key sequence the macro was built from |
| `logs/*.txt` | UI.Vision's own run log for each run (`savelog`) |
| `../run_sheet_uivision.csv` | UI.Vision rows + Intern's existing rows, for `rpa_score.py` |

## What to disclose in the paper

- UI.Vision has no desktop recorder and cannot read a native app's controls, so the macro is
  keyboard-driven (one click, then Tab order). Image matching was not used because the modified
  form changes every colour.
- The macro was generated by an AI coding assistant from the form's Tab order, so its setup time
  is not human effort.
- UiPath and Power Automate Desktop, which select controls by name, were still not tested.
